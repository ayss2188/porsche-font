# v4.1.0 更新说明

## 📮 先拜托一件事：遇到问题请把诊断报告发我

这个模块**没有按机型做适配**，靠的是"读你自己的字体配置"自动判断该换哪些字体。
这套机制**能让你直接用上**，但它是**兜底**，不是适配 ——
**"哪些字体该换却没换"这类问题，只有报告里看得出来，作者在代码里是猜不到的。**

所以：

- **能用 ≠ 没问题**。你可能觉得"字体换上了、看着正常"，但报告里可能显示
  某个槽位根本没进计划、某个角色的字体被跳过了、或者本该换的配色没生效。
- **换过配色、或者刷在非小米机型上的，尤其建议发**。你的机型可能和作者手上的不一样，
  出问题的概率更高，而报告一点就能看出来。
- **确认没问题也值得发**。"查过、没缺口"同样是结论，可以写进下一版的记录里备查。

**怎么发**：设置页 →「诊断报告」→ 生成完 → 把 `Download/完整体检报告.txt` 发给我。
（生成要点时间，可以关窗口去干别的，任务在后台继续。）

## 一、修复：**三套配色字体内部的元数据缺陷**（可能导致个别 App 闪退）

三份字体（素装 / 一点红 / 烈焰）内部有三个字段写错了：

```
① 对外自称"我是粗体 + 斜体"     ← 其实两个都不是
② 自称"我的字重是 330"          ← 但它是去顶替"字重 400"的位置
③ 样式栏一个字都没填            ← 该填"普通体"
```

**为什么这个要紧**：已经有用户反馈"**装了这个模块之后，个别应用打开就闪退**，
恢复默认字体就正常"。查下来崩溃特征很特殊：

- 系统日志说 `isCrashing=false`（系统不认为它是崩溃）
- `SIGNALED_UNKNOWN` + **Java 层完全没有任何异常栈**
- 前台可见、启动后几秒反复死亡

也就是说**进程是被静默打死的**，普通排查根本查不到。定位到的原因就是上面这三个字段 ——
系统解析字体时会读它们，声明与实际不符会让解析路径进入不一致状态，
在自带 native 校验的加固应用上就足以打死进程。

**修法**：每份字体只改 **3 个字节**。字形数据**一个都没动**，
文件大小完全不变，**字的形状一个像素都不会变**。

> ⚠️ 老实说一句：**"这三个字段就是闪退根因"目前还是推断** ——
> 证据链是完整的（症状吻合、其它原因已逐项排除），但**我们还没在真机上验过**
> "装上修复版之后那个 App 就不闪退了"。
> **所以特别需要你反馈**：如果你之前遇到过"某些 App 闪退、换回默认字体就好"，
> 更新后请再试一次那个 App，然后告诉我结果。

## 二、修复：**"没适配过的机型"其实一直没被兜住**

本模块有一个设计：**不知道你是什么机型时，靠"读你自己的字体配置"自动兜住** ——
扫一遍你机器上的字体配置，减掉已知清单里有的，**剩下的就是没人管的，模块自己接管**。
所以就算你的机型我们没适配过，装上去也能用。

**但这条链路断了**（早前一次"提速"改坏的，改完看着像优化，实际把整段功能关掉了）：
它本该去"扫描设备配置"，结果改成拿"清单已经算出来的候选"来扫 ——
**从已经有的里面挑，当然挑不出新的**。于是自适应等于关闭。

而且这个 bug **只有没适配过的机型会踩到** —— 恰好是最需要它的那些机器；
报告里也看不出来（报告会说"模板已覆盖本机需要的角色"）。

顺手修掉同一条链上的第二个 bug：扫描结果里 **`lang="und-Nkoo"`（西非 NKo 文字）**
因为语言码里含 "ko" 被当成**韩文**、`lang="und-Java"`（爪哇文）含 "ja" 被当成**日文** ——
真补进去的话，**这两种文字会被换成你的字体、变成方块**。

实测（模拟一台"完全没适配过"的机器）：

```
修前：计划 = main + cjk                      ← 韩文/日文永远不换
修后：计划 = main + cjk + hangul + kana       ← 补对了
      NKo / 爪哇文 没有被误换                  ← 也没换错
```

> **这一条正是上面"请发诊断报告"的原因**：自适应能兜住大部分，但兜不住的部分
> 只有报告能看出来。你发一份，我就能把你那台机器补成"原生适配"。

## 三、新增：发版前会先体检字体

加了自动检查：以后每次发版前都会先验一遍上面那三个字段，
**不会再让有缺陷的字体发出去**。

## 四、修复：诊断报告两个视图的框大小不一样

有用户反馈"切到原样文本，框缩成中间一小块、什么都看不到"。实测（量真实高度）：

| 内容 | 修前：结构化 / 原样 | 修后 |
|---|---|---|
0 节 | 90 / 90 | **349 / 349** |
1 节 | 104 / **90** | **349 / 349** |
1 节+未完成 | 186 / **90** | **349 / 349** |
12 节 | 339 / **90** | **349 / 349** |

原因：两个视图在弹窗布局里被压到 90px 下限（**原样文本永远只有 90px**），
而结构化视图跟着内容变 → 两个框大小不一致、其中一个看着"什么都没有"。
现在两者用同一套规则、都填满可用空间、都不许被压扁。

## 五、一并同步：清单与角色判定的三处修正

- **`SFPRO-SemiCondensedBold/Light.otf` 以前被判成"符号字体" → 永远不替换。**
  原因是角色判定里 `*icon*` 这个匹配命中了 "sem·**icon**·densed"。
  如果你用的是**魅族手机**，这两个文件此前一直没被换过，现在会正常参与替换。
- **魅族自有字体补进清单**（`SFDIN-*` / `SFPRO-*` / `DMSerifDisplay` / `FlymeNumber-VF`
  等 19 个）：以前只在字体配置引用到的时候才生效，**换一套魅族固件就会静默漏掉**。
- **新增三星 One UI 专属字体清单**（`targets/samsung.list`，33 个槽位）：
  以前 `targets/` 里五份清单**没有三星**。本模块刷到三星机器上时，
  能多接管 `OneUISansKR-VF`（韩文界面字体）、`ComingSoon`、`DancingScript` 这几个
  以前"报告里看不出来、但确实没被换"的槽位。

> 这几条对**小米 / 一加 / OPPO 那类机型没有任何影响** —— 那些文件名在那些机器上不存在。

## 六、一并修掉的"不报错但结果不对"

两条**升级后才发现不对**的问题（都是静默的，界面上不报错）：

- **恢复上次选择的解析链**：跳过空值和 `none`、优先读"当前真正生效"的那个。
  以前 `pending_font` 里写着 `none` 会挡住后面所有来源 → **升级完字体没了**。
- **兜底结果不再被覆盖**：兜底挑好字体后，紧接着一句无条件的"清成无字体"又把它盖掉
  → 用户重启回到默认、**必须重新选一次**。

## 七、一并修掉的更新日志截断

`update.sh` 读更新日志时限制了长度，上限原本是 30000，
而日志文件已经超过这个数 —— **后 5 个版本用户根本看不到**。

> ⚠️ 注意 `head -c` 数的是**字节**不是字符，中文一个字占 3 字节 ——
> 所以中文日志的"可显示上限"其实只有两万字左右。
> 这个上限已恢复成 60000，**你现在点「更新日志」能看到全部历史版本**。
