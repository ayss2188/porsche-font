### 一、修复：**字体"刷了不生效、切回无字体、一直转圈"**（重要，建议更新）

#### 现象

有用户反馈：刷上字体后**中文全变方块 → 自己切回无字体 → 再选也一直转圈**。
看起来像"模块把系统搞坏了"，实际不是。

#### 真相：字体库里留了一个 **16 字节的坏文件**

报告显示，字体库里除了真正该用的合集（几十 MB），还多了一个**只有 16 字节**的同名文件。
而挂载日志**每次开机都在重复同一句话**：

```
跳过无效字体（不挂到系统槽上）: …ttc5_2-3 -> /system/fonts/NotoSansCJK-Regular.ttc
跳过无效字体（不挂到系统槽上）: …ttc5_2-3 -> /system/fonts/NotoSerifCJK-Regular.ttc
```

**16 字节里当然没有字体** —— 但根子不在"文件坏了"，而在**模块没认出它坏了**：

```
判断"一个 .ttc 有几个 face"时，只查开头 4 字节是不是 "ttcf"
→ 16 字节的垃圾头部正好也是 "ttcf"，于是它自称"我有 5 个 face"
→ 模块认为这个文件**结构完全正确** → 一直留着 → 每次开机拿去挂载 → 每次失败
```

**修了两处，都是"与实现无关的硬底线"：**

| 修复 | 效果 |
|---|---|
合集判定加 **100 字节下限** | 16 字节垃圾 → 报 **0 个 face**。一个 TTC 的头就有 `12+4×face数` 字节、每个 face 表目录至少 28 字节，**真合集不可能小于 100 字节** |
合集产物加 **1KB 兜底** | 产物不到 1KB 就是坏的 → **直接删掉**，下次重新合成 |

#### 顺手确认了一件事

用报告里那份字体逐字节复现，实测**合成本身是好的** ——
产物 47,336,064 字节、魔数 `ttcf`、5 个 face 名字全对。
**不是合成坏了，是判定太松。**

### 三、修复：**坏字体现在会被拦下，不会再挂到系统上**

有用户反馈「桌面、设置全是方块，有的 App 正常」。报告里查到根因：
他导入的字体**内部没有任何字形轮廓**（缺 `glyf`/`CFF`）——
**自称有几万个字形，但存字形的表根本不存在** → 系统取不到字形，只能画空格子。

**这个字体是旧版本模块导入的** —— 那时还没有这道检查，所以一路挂到了系统上。

#### 现在有两道关

| | 什么时候拦 | 拦什么 |
|---|---|---|
**第一道** | **导入时** | 魔数不对、文件截断、缺必需的表、**没有字形轮廓** —— 直接拒收 |
**第二道**（这一版新增） | **应用前**（每次切换 / 重新生成） | 再验一遍**有没有字形轮廓** |

**为什么第二道必须有**：字体库里可能已经躺着旧版本导入的坏字体。
第二道在真正挂载之前再验一次，**遇到就拒收并说明原因**，不会再让系统变方块。

**所以以后遇到不能用的字体，不用重启一次才发现** —— 它会当场告诉你原因，换一份就行。
校验通过的结论会**记下来**，以后切换不用再把它读一遍。

#### 过程中修掉了这个检查自己的一个 bug

第一版是"把文件头部洗成词表、再精确匹配 `glyf`"，但**表目录里 tag 后面紧跟的是二进制校验和
—— 字母数字的字节会和 tag 粘成一个词**（实测洗出来是 `glyfY`），
于是**有 glyf 的好字体被判成空壳**。已改成**按 16 字节一条读表目录**（字体的真实结构）。

### 四、新增：**「保留锁屏时钟字体」开关**（小米/红米/POCO 机型）

小米系的**锁屏时钟有自己专用的一份字体**（`miclock-*` / `mitype-clock` / `MiClock.otf` 这类），
以前它们会跟着一起被换掉 —— 结果就是**你在系统里换锁屏时钟样式，样式变了但字形还是你那套字体**。

**这一版加了一个开关**（设置页 →「替换范围」里，默认**关**）：

| 开关 | 行为 |
|---|---|
**关**（默认） | 连锁屏时钟也换成你的字体 —— 和以前一样 |
**开** | 那几份锁屏字体**保留原样**，你还能在系统里挑锁屏时钟样式；**其余所有槽位照旧全替换** |

**判据是精确的**：按 **family 名里带 `clock`** 认，不是靠"是不是特殊字体"这种模糊猜测。
实测实机：**认出 34 个锁屏字体，全部正确、无一个误伤**。

> 其他厂商的机型**没有**锁屏专用字体族，这个开关开了也不影响任何东西。

### 五、优化：**切换配色更快了**（少做重复的活）

切换背后要做几件"扫描"的活，而结果**平时根本不会变**（配置没改、清单没改），
以前却每次都要重算一遍。这一版把它们**存起来了**：

| 存什么 | 什么时候重算 |
|---|---|
**哪些字体是锁屏专用字体**（开了「保留锁屏时钟字体」才用到） | 系统字体配置变了 |
**这台设备有哪些"没人管"的字体**（自适应扫描的结果） | 配置 / 清单 / 字体目录变了 |

**存的是结果，不是猜测** —— 缓存和重新扫出来的**结果完全一致**（比对过），
只为省掉重复劳动；一旦上面任一条件变了会自动重扫，不会用旧结论。

### 六、修复与优化

- **报告的"每一步耗时"有两处是错的**：`PZ1 TTC头信息` 原来记的是它**前面**那段的耗时，
  TTC 段根本没被测到（那句"223 秒"就是错的，会把人带偏）。已拆成两条，各自记自己那一段。
- **报告生成更快**：原来"打包哈希清单"是**每个文件起 2 个进程**读大小和修改时间
  —— 字体目录大的机器 200~270 个文件、1 GB 以上，也就是 **400~550 次进程创建**。
  改成"每个目录一次读完、之后查表"，实测**结果逐字节完全相同**、全量回归 **12 套件 0 失败**。
- **诊断报告界面**：去掉了重复的横幅文案；去掉了所有"可以关窗口 / 任务在后台继续"的提示
  —— Android 会把后台的 WebView 冻住甚至杀掉，"关掉"其实等于"取消"，说了反而误导人。
- **更新进度现在能看全了**（原来那一版几乎看不见过程）：
  - **以前**：点更新之后，进度条停在「准备中」，然后**一瞬间就跳到"已更新完，请重启"** ——
    中间下载了多少、装到哪一步了，完全看不到。字体包几十 MB、装机又要十几秒，
    这段时间界面像卡住一样，很容易让人以为死机了，然后手贱去关窗口。
  - **现在按顺序给你看**：
    ```
    正在连接 GitHub…  →  正在下载刷机包 12.3 MB / 45.7 MB（27%）
                      →  正在校验刷机包…  →  安装完成，重启后生效
    ```
    - **下载阶段** —— 按实际收到的字节数走，**已下载 / 总大小 / 百分比**都实时在变；
    - **安装阶段**（新增）—— 按安装器日志的**增长量**和**已用时间**双重估算，进度条会真的走，
      不再是一进去就 100%。
  - **卡住会提醒**：连续十几秒字节数完全没变，会提示"下载好像卡住了…还在重试，如果一直不动可以换网络再试"
    —— 只提醒、**不中断**，免得网络一抖动就把已经下好的部分丢掉。
  - **失败会说清楚是哪一步失败**（下载 / 校验 / 安装），不再静默跳完。
- **底部按钮**：修掉了窄屏上被挤没的问题（小屏 / 大字体设置下）。
